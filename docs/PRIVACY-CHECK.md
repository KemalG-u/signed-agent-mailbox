### 3.3 Why the role label for the human operator was not renamed

A generic name (for example `human`) would suit a public tool better, but renaming it changes behaviour, so it was not done:

- The label is one of the values accepted by `--kimden` (`KIMDEN` in `kutu.py`, enforced as argparse `choices`). After a rename, the old value is rejected for every existing script.
- Records already stored in a box keep the old label; the sender filter (`--kimden-haric`) and the page styling match by label, so they would stop matching those records.
- The label is a signed field of each record (`kimden`) and the key file is looked up by the sender name, so the label is part of the signature format, not only a display name.
- The page generator derives the CSS class and the colour variables from the label, and the unit tests assert the generated markup (the example page was generated by the same code and carries the label as a class name).
- The authority prefix that is delivered to the receiving agent refers to "the box owner" generically (Turkish text: it tells the agent to ask the box owner when a request conflicts with the owner's rules). The tests assert this exact text; changing it changes what agents are told.

`Interpretation:` A rename would need a compatibility alias and a new default text; that is a feature change for a later commit, not a cleanup. This was not done in this release preparation.

Remaining intentional occurrences: the copyright holder name in `NOTICE`, the maintainer name in `docs/AI-USE.md`, the account name in repository links, and the role label described above.

## 5. Independent second reading

A fresh-context reviewer agent reads the exact release candidate commit adversarially, after the last commit, and the result must be `passed` on that full SHA. The reader is an AI tool; this is an additional read, not a sign-off. The reading result and the full SHA are recorded in the maintainer's release record (outside this tree) and, after publication, in section 7. A commit cannot contain its own SHA, which is why this section describes the rule and section 7 holds the result.

## 6. Limits

`Interpretation:` Scanners can miss secrets and can flag placeholders. A clean result lowers risk; it does not prove absence. The pattern scans of `kontrol.py` are heuristics (they match drive-letter and home-folder shapes, not every possible local detail). The grep gates below are exact-string checks over the tracked and untracked files of the tree and do not look inside binary data. The history scans cover a single commit at the time of writing.
