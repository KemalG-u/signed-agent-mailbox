# Contributing to kutu

Thanks for considering a contribution. This project is small and maintained by one person; clear, tested, focused changes are the easiest to review. Please follow the [Code of Conduct](CODE_OF_CONDUCT.md).

## Before you start

- Open an issue first for anything larger than a typo or a one-line fix.
- Check [docs/decisions/](docs/decisions/) to see whether the design question was already decided.
- Report security problems privately, not as issues: see [SECURITY.md](SECURITY.md).

## Development setup

```
git clone https://github.com/KemalG-u/signed-agent-mailbox.git
cd signed-agent-mailbox
python -m unittest discover
```

All tests must pass before you open a pull request. Add or update a test for every behaviour change.

## Commit messages

Use [Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0/) so the changelog can be generated by [git-cliff](https://git-cliff.org/):

```
feat(scope): add something users can see
fix(scope): correct the wrong behaviour
test(scope): cover the missing case
docs: explain the new option
```

## Pull requests

1. Keep a pull request focused on one change.
2. Describe the problem, the fix, and how you verified it (command and result).
3. Do not include secrets, personal data, local file paths or raw AI-agent logs.

## AI use

AI tools are allowed under these rules. They follow the common core of other projects' policies ([LLVM](https://llvm.org/docs/AIToolPolicy.html), [Ghostty](https://github.com/ghostty-org/ghostty/blob/main/AI_POLICY.md), [Linux kernel](https://docs.kernel.org/process/coding-assistants.html)).

1. **You are responsible.** You must understand every line you submit, have run it, and be able to explain it in review. "The AI wrote it" is not an answer to a review comment.
2. **Disclose.** State significant AI assistance (tool or model, and for what) in the pull request description, and mark it in the commit with a trailer: `Assisted-by: TOOL:MODEL` (example: `Assisted-by: ExampleAgent:example-model-1`). Routine editor autocompletion needs no disclosure.
3. **No human sign-off by proxy.** An AI tool must never add `Signed-off-by` (or any certification of origin). Only a human can certify a contribution.
4. **No unreviewed output.** Pull requests that look like unreviewed, bulk or autonomously generated output (invented APIs, unrelated changes, boilerplate explanations) will be closed.
5. **No private data in prompts or patches.** Do not paste secrets, personal data or someone else's code you may not relicense.
6. **Copyright.** Purely machine-generated material may not be protected by copyright; keep your own human contribution substantial and be able to say what it is.

How this project itself uses AI: [docs/AI-USE.md](docs/AI-USE.md).
